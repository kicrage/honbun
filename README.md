# Honbun（Chrome / Edge 拡張）


国立国会図書館「次世代デジタルライブラリー（テキストモード）」が表示している **ページ（コマ）ごとのOCRテキスト** を、書籍単位でまとめて `.txt` / `.md` に保存する拡張機能です。

デジタルコレクションの全文テキストや通常モードの全文は頁の混線が多く使えませんが、テキストモードは頁ごとに行単位のOCRレイアウトを取得して表示しているため混線がありません。この拡張は、そのテキストモードと同じデータ（`/dl/api/page/layout/{PID}_{コマ}`）を取得して整形します。

## インストール（開発者モード）

```bash
npm install
npm run build        # dist/ に拡張が生成される
```

1. Chrome / Edge で `chrome://extensions`（Edge は `edge://extensions`）を開き、「デベロッパー モード」をオンにする
2. 「パッケージ化されていない拡張機能を読み込む」で、このフォルダの **`dist`** を選ぶ

## 使い方

1. 次のいずれかの状態にする
   - **テキストモード** `https://lab.ndl.go.jp/dl-text/book?pid=…&page=…` を開く
   - **通常のデジタルコレクション** `https://dl.ndl.go.jp/pid/…/1/…` を開く
   - **それ以外のページ**: そのままでよい（拡張側で PID を入力する）
2. ツールバーの拡張アイコンを押す。設定メニューが開く
   - 上の2つでは資料と現在のコマが自動検出される
   - それ以外では **PID（永続的識別子。例 `1234567`）または資料の URL** を入力して「読み込む」。
     （12桁の書誌IDは PID とは別のものです）
3. 範囲・書式などを設定する（「プレビュー」タブで現在の設定の仕上がりを確認できる）
4. 「◯コマを .txt に出力」を押す。ダウンロードフォルダに保存される

「サイドパネルで開く」を押すと、閉じない常駐パネルで同じ画面を使える（変換中もフォーカスが外れて中断されることがない）。

## 設定

| セクション | 内容 |
|---|---|
| 範囲 | 開始/終了コマ（既定は **現在のコマ〜最終コマ**）、目次からの範囲設定 |
| OCRデータ | **コマずれの補正**（自動検出／手動指定）、**レイアウトに載らなかった文字の補完**（字体を旧字体にそろえる、柱を含めるか） |
| 分割とラベル | 見開き（1コマ＝紙面2頁）を右頁・左頁に分割／綴じ位置／読み順／頁ラベル（`{page}頁`・`p.{page}`・自由書式、算用・全角・漢数字）／位置／頁区切り／印刷頁の算出方法 |
| テキスト整形 | 取り込む行の種類（本文・タイトル本文・注・キャプション）／外字 `〓` の扱い／行内空白の除去／OCR行の連結（段落化）／ブロック間の空行／頁番号（ノンブル）行の除去 |
| 出力 | **形式（TXT 既定／Markdown）**、1ファイル結合／コマごとzip、ファイル名テンプレート、サブフォルダ、「名前を付けて保存」、BOM、改行コード |

- 印刷頁の番号は、書誌の目次（章ごとの頁とコマ）から算出する。OCRのノンブルは誤読が多いため使っていない。
- 保存先は、ブラウザの制約によりダウンロードフォルダ配下のサブフォルダか、「名前を付けて保存」で選ぶ。

## OCRデータの注意（コマずれと欠落）

テキストモードのデータには、資料によって次の問題がありますが、この拡張機能では自動検知により対処する機能を備えています。

- **コマずれ**: 登録時の不備で、OCRデータが画像と1コマ以上ずれている資料については、書誌の目次の見出しが現れるコマから自動で検出し、出力のコマ番号・頁番号は画像（デジタルコレクションの閲覧画面）に合わせます。
  - テキストモードの URL の `page=` はデータ側の番号なので、拡張は画像のコマへ換算して「現在のコマ」を示します。
- **欠落**: テキストモードの行データ(layout)に載らない文字がある場合、文字単位OCRには座標つきで残っているため、載っていない文字を桁ごとに行へ組み直して補います。
  - 柱・ルビ・頁番号は補わず、字体は全文OCRの旧字体に揃えています（そろえられないコマは新字体のまま。完了時に件数を表示）。

## 開発

```bash
npm run dev          # 開発サーバ（/dl/api は lab.ndl.go.jp へプロキシ）。
                     #   http://localhost:5173/app.html?src=<資料のURL> で、アクティブタブのURLを模擬できる
npm test             # 単体テスト（Vitest）
npm run typecheck
npm run build
npm run icons        # アイコン(PNG)の再生成
```

構成:

- `src/core/` … 拡張APIに依存しない純ロジック（API取得・layout XML 解析・見開き分割・頁番号算出・整形・TXT/MD出力）
- `src/ext/` … `chrome.*` ラッパ、URL解析
- `src/ui/` … MUI による画面（ポップアップ／サイドパネル共通）
- `tests/` … 単体テストと

## 制約

- ポップアップはフォーカスが外れると閉じるため、長い書籍はサイドパネルでの実行が推奨されます。
- 印刷頁は目次の項目を基準にした算術推定であり、区間内に頁番号のない挿図コマがあるとずることがあります（設定で基準を手動指定できる）。
- 旧字体→新字体変換、文字単位OCR（ルビ除外）モード、Firefox は未対応です。
- テキストモードの画面が閲覧時に取得するのと同種のリクエスト（既定4並列）を取得するものです。
